## What this is

A small voter contact tool for a field program: import a voter file, cut phone lists and door knocking turfs, assign them to volunteers, log each contact attempt, and report contact rates and support IDs. It is a demo. All voter data is generated by `scripts/generate-voters.ts`.

## Commands

| Command | What it does |
|---|---|
| `docker compose up -d` | Postgres 17 on port 5433 with `votercontact` and `votercontact_test` |
| `npm run dev` | App on http://localhost:3000 (reads `DATABASE_URL` from `.env`) |
| `npm run seed` | **Wipes** `DATABASE_URL` and loads the sample file, volunteers, lists and contact history. Refuses a non-local database unless you pass `--yes`. |
| `npm run seed:production` | Same, against the hosted database in `.env.production.local` (from `vercel env pull`) |
| `npm run generate` | Rewrites `public/sample-voters.csv` (same seed, same file) |
| `npm run screenshots` | Recaptures the dashboard images on the intro page and `public/og.png` (needs the app running and seeded) |
| `npm run test:unit` | Unit tests only, no database |
| `npm test` | Unit + database tests (database tests use `TEST_DATABASE_URL`) |
| `npm run test:e2e` | Builds the app, starts it on port 3100 against `TEST_DATABASE_URL`, seeds it, runs Playwright |
| `npm run check` | Lint + typecheck + unit and database tests. Run it before calling a change done. |

## Rules

**Data**
- Fake data only. Never add, paste or commit real voter data, real names with addresses, or real phone numbers. Generated phones use area code 555, which is not in service.
- Never invent facts on the intro page: no made up user counts, testimonials or stats. Every claim there must be true of this demo.
- Don't log voter details (names, phones, addresses) to the console or error messages.

**SQL**
- Every value goes in as a `$n` parameter. Never put a value from a user, a file or a URL into SQL text.
- The only SQL built in code is from fixed fragments: `buildSegmentWhere()` and `listOrderBy()`. Extend those; don't add string building elsewhere.
- Cast counts to `::int` (Postgres `count()` is bigint and `pg` returns bigint as a string).
- Row types mirror column names (snake_case). Function inputs are camelCase.
- Schema change: edit `db/schema.sql`, keep `constants.ts` in sync with its check constraints, and add a database test. There are no migrations in this demo; `npm run seed` rebuilds.

**Validation and errors**
- Validate at the boundary with zod: CSV rows (`csv.ts`), form data (Server Actions), URL params (`parseSegmentParams`). Functions in `src/lib` take typed values.
- Throw `UserError` for anything the person can fix (bad input, empty segment, unassigned list). Server Actions turn a `UserError` into `{ ok: false, error }` and rethrow everything else.
- The database has the last word: constraints reject a contact for a voter not on the list and a support ID without a conversation. Keep those even when the UI already prevents it.

**UI** (details in the landing-page-design skill)
- Text uses the named styles from `globals.css` only: `heading-1`…`heading-6`, `title-1`…`title-5`, `body-1`…`body-6`, `button-lg/md/sm/xsm`, `caption-1`…`caption-5`. No loose `text-sm font-medium`.
- Spacing only from 0, 2, 4, 8, 12, 16, 24, 32, 40, 48, 64, 80, 96px (Tailwind `0.5 1 2 3 4 6 8 10 12 16 20 24`). Buttons are `px-3 py-2`; use `buttonClass` / `smallButtonClass` / `secondaryButtonClass` from `ui.tsx`.
- Colors come from the tokens in `globals.css`. Dark backgrounds only from #000000 #181818 #1F1F1F #272727 #313131 #131209. No background gradients; the hero heading is the one gradient (`hero-gradient`).
- Icons: Phosphor only. Server Components import from `@phosphor-icons/react/dist/ssr`, Client Components from `@phosphor-icons/react`.
- Motion: the default curve is `cubic-bezier(0.22,1,0.36,1)` (set in the theme). Animate transform and opacity only, put movement behind `motion-safe:`, and use `Reveal` (IntersectionObserver) for scroll reveals.
- Every data page has a skeleton fallback shaped like its layout (`skeletons.tsx`) and a composed `EmptyState`. Errors are inline (`role="alert"`), never `alert()`.
- Copy: sentence case, no hyphens in UI text (write "score 40 to 60", not "40-60"), no exclamation marks, calm and specific system messages. Check new pages at 390px wide: no horizontal overflow.

**Next.js 16** (see `AGENTS.md`; the docs for this exact version are in `node_modules/next/dist/docs/`)
- `cacheComponents` is on. Every data page has one shape: the default export renders what needs no data (title, forms) and wraps one async component in `<Suspense fallback={<…Skeleton />}>`; that component calls `await connection()` before its first query. Copy an existing page. The dev server logs an error if a query runs outside `<Suspense>`.
- Mutations are Server Actions in the route's `actions.ts`. They call `refresh()` after a write, or `redirect()` to a new page.
- Client Components (`"use client"`) never import a module that imports `db.ts`. Pass data down as props.
- React resets a form after its action. A select showing a saved value gets `key={value}` so it remounts with the new one; don't make placeholder options `disabled` (a reset select falls back to the first enabled option).

**Tests**
- Behavior change → write or change the test first, watch it fail, then change the code.
- Pure logic gets a unit test (`*.test.ts`). Anything that runs SQL gets a database test (`*.db.test.ts`), which runs against a real Postgres and resets it in `beforeEach`.
- A user-visible flow gets covered in `e2e/`. Use `getByRole` / `getByLabel`: Next keeps recently visited routes in the DOM, hidden, and those locators skip hidden elements.
- Don't weaken or delete a failing test to get green. If the test is wrong, say why in the commit message.
- The reset helpers refuse any database whose name doesn't end in `_test`. Don't remove that guard.

**Deploy** (Vercel + Neon; steps in the README)
- Secrets live in Vercel env vars and `.env*` files, which are gitignored. Never commit a connection string.
- `CRON_SECRET` protects `/api/reset-demo`. Without it the route refuses every request.

## Domain terms

| Term | Meaning |
|---|---|
| Voter file | The uploaded CSV. `voter_id` is its key; uploading it again updates rows. |
| Support score | 0 to 100 from the voter file. Modeled likelihood of supporting our side. |
| Support ID | 1 to 5, recorded in a conversation. **1 = strong support**, 3 = undecided, 5 = strong oppose. |
| Segment / universe | The filter: precincts, parties, age range, score range, contact history. |
| List / turf | A snapshot of the voters a segment matched when it was created, in call order (phone) or walk order (door: precinct, street, house number). |
| Attempt | Any logged contact. |
| Conversation | An attempt with outcome `reached`. |
| Contact rate | Conversations ÷ attempts. |
| Supporters ID'd | Distinct voters who gave a 1 or 2. |

## Definition of done

1. `npm run check` passes.
2. `npm run test:e2e` passes if anything a user can see changed, and new UI was checked at 390px wide in light and dark mode.
3. `docs/plan.md` is updated if a decision in it changed.
4. Commits are one feature each, with a message that says what changed and why.
